# 07 验收标准

本文定义通过条件，不代表这些检查已经在当前环境完成。每次交付记录实际命令、平台、结果、截图位置和未验证范围；未执行的原生或视觉检查标为“尚未验证”。

## 功能与错误恢复

- 应用进入概览页，侧边栏能切换概览、记录和组件页。
- 示例记录可生成、查看、编辑和删除；删除经过确认，页面只通过 repository 访问数据。
- 超过 20 条的示例记录仍全部可达，计数和状态筛选覆盖完整结果。
- 详情切换记录后，旧请求、保存或删除的迟到结果不会污染当前记录或改变当前导航。
- 设置保存浅色、深色、系统主题偏好；命令面板可以搜索并执行导航或设置操作。
- 列表与详情区分加载、读取失败、成功但无数据；读取失败时持续显示说明和重试入口，不误报空数据或记录不存在。
- 列表刷新失败保留上次成功结果并提示尚未刷新；成功重试后清除提示。
- 保存返回 `null` 或抛错时不提示成功、不丢失输入；记录已不存在时提供返回列表入口。成功返回记录后才退出编辑，成功或取消后清除保存错误。
- 原生连接并发请求共享一次加载，成功后复用；失败后的下一次调用允许重建连接，不自动重试或回退到 mock。
- 骨架源仓库保持中性示例；派生项目更新产品定位，并保留分层及验证约束。

## 原生、窗口与验证条件

- 浏览器和 mock 测试不能替代真实 SQLite 的操作、退出重启和只读核对。
- 默认与最小支持窗口、明暗主题下，主要操作可达且键盘交互正确。窗口和视觉目标以 [DESIGN](../../DESIGN.md) 为准。
- 日常检查按影响范围选择；骨架完整验收需要自动基线、相关原生运行和视觉证据。
- 检查命令、隔离数据目录、实际操作和证据方法统一见 [工程验证](../tech/engineering.md#验证范围)。未运行的平台和路径必须标为“尚未验证”。

## 复用演练与完成条件

骨架定版时，让未参与编写指南的开发者或代理按 [开发者入口](../tech/developer-start.md) 在临时副本中完成一次派生演练：

- 使用独立应用 identifier 和数据目录，把示例替换为中性笔记实体，将表名改为 `notes`、`summary` 改为 `body`，同步类型、mapper、repository、SQL、描述、mock、页面、路由和测试。
- 完成浏览器预览及原生读写、退出重启，并确认原始骨架的数据未被共用。
- 将遇到的说明缺口补回现有指南；演练业务不进入骨架源仓库。

定版要求：错误反馈真实可恢复；设计、开发规范与实现一致；支持的窗口和主题有画面证据；原生持久化有读写及重启证据；新代理可以依项目文件完成派生开发。没有 schema 变更时不额外建设旧库升级测试体系；今后有兼容性迁移时验证相应升级路径。
